Making Cowrie

Why five decades of data formats fractured across the AI stack, how one 799 KB canonical container (with an 81.1 KiB gzipped WebAssembly build and a Lean-kernel-verified Bend 2.0.35 formal proof suite) unifies them, fifteen measured wins across four symmetric live runtimes and an MCP wire firewall, eleven engineering postmortems and formal audit catches, and what it changes for local and cloud inference.

Workstation: RTX 3090 · Ryzen 7 7700X (SHA-NI + AVX2) · NVMe Core: libcowrie_core.so (799 KB) · cowrie_core.wasm (80.7 KiB gzip) · PROOF.bend (26/26 laws) github.com/Neumenon/cowrie

A single AI request today crosses six incompatible serialization formats before it finishes. An agent fetches HTML as UTF-8, wraps the result in JSON, prints a 1,536-float embedding as ASCII digits, stores a visual workflow in a key-order-sensitive graph, discards gigabytes of prefilled GPU state whenever a process restarts or swaps models, and glues system policy and untrusted external text together with string delimiters. Every hop copies memory, drops cryptographic identity, busts caches, and leaves privilege boundaries unenforced.

Cowrie (v1.2.0) is a single canonical binary container and live runtime substrate designed for all three hardware readers that touch modern AI data: language models, GPU tensor cores, and CPU security verifiers. Its core compiles offline in under four seconds from zero-dependency Rust into one 799 KB native library (libcowrie_core.so), an 80.4 KiB gzipped WebAssembly module (cowrie_core.wasm), and a standalone MCP wire proxy running with full feature symmetry across four distinct engines: Eureka LLM, Eureka Creative Engine v7, llama.cpp, and vLLM 0.15.0. Every metric in this document comes from receipted runs on one physical workstation; every failure and security audit catch we hit along the way, and every boundary where JSON or columnar OLAP still wins, is reported directly.

01History & Motivation

How Fifty Years of Data Formats Diverged

Every major serialization format of the last half-century solved the physical bottleneck of its own era. The problem facing AI stacks in 2026 is not that JSON, Protocol Buffers, CBOR, Parquet, or Safetensors failed — it is that each optimized for one hardware reader and diverged irreversibly from the others.

Era 1 (1970s–2005): Human text and web RPC

CSV, XML, YAML, and JSON won software engineering because humans could inspect them in any terminal and browsers could parse them in one call. For HTTP REST APIs, encoding freedoms such as arbitrary key ordering ({"a":1,"b":2} vs. {"b":2,"a":1}), signed zero (-0.0), and equivalent number spellings (1, 1.0, 1e0) carried zero cost. Once cryptographic content addressing and LLM KV prefix caching arrived, those freedoms turned into silent cache misses across Python, Rust, C++, and JavaScript clients.

Era 2 (2008–2016): The split between fast RPC and content hashing

Microservices outgrew text parsing and fractured into two camps. Protocol Buffers and FlatBuffers delivered fast typed RPC while explicitly disclaiming deterministic canonical bytes: unknown fields, map iteration order, and omitted defaults allow two valid encoders to emit different hashes for the same logical record. On the other branch, CBOR and DAG-CBOR (IPLD) solved deterministic hashing, yet remained unaligned sequential byte streams incapable of zero-copy 16 KB GPU mapping or hardware DMA.

Era 3 (2016–2024): The split between analytics and static model weights

Data warehouses adopted Apache Arrow and Parquet for contiguous SIMD scans, while machine learning replaced Python pickle (capable of arbitrary code execution on load) with Safetensors and GGUF so static model weights could map cleanly off disk into GPU memory via mmap. Both solved static weights, leaving everything produced at runtime (live KV caches, recurrent SSM state, agent transcripts, multimodal embeddings, ComfyUI node graphs, and filtered vector indexes) stranded across six disconnected tools.

Era 4 (2026): Three incompatible readers collide on one record

When a neural network enters the read-write loop, three hardware subsystems operate on the same artifact simultaneously: the LLM attention engine pays in tokens and quadratic attention work; the GPU tensor core requires contiguous little-endian buffers aligned to hardware memory pages; and the CPU verifier requires zero-allocation bijective hashing and out-of-band privilege boundaries. Compact text dialects address only the first reader while leaving GPU buffers, cross-language identity, and security boundaries unsolved.

02Architecture Layered With Wins

Four Planes, Each Tied Directly to a Physical Payoff

Cowrie is structured so that every byte-level decision exists to produce a concrete runtime win. Walking Plane A through Plane D shows how each architectural invariant creates its measured payoff directly at the hardware boundary.

Plane A · Bijective Canonical WireZero-Allocation Verification, Native 0x0A TensorRefs & Satellite Isolation

Every Plane A frame begins with an 8-byte header: magic "COWR" (43 4F 57 52), version 0x01, out-of-band authority (byte 0x05), epistemic tag, and flags = 0x00 (compression belongs to transport, never identity). A key dictionary sorted strictly in UTF-8 byte order follows, then a minimal value tree: 0x40..0xBF inline FIXINT, 0x04 canonical f64 with -0.0 → +0.0, 0x03 zigzag Int, and native TAG_TENSOR_REF (0x0A) Coordinate Contracts (cutting tensor reference wire size by −47.4% from 78 B to 41 B while validating overflow-safe shapes against Plane C). Hardened in v1.1, verify_frame_zero_alloc checks every canonical rule using a stack-inline [u64; 4] key bitset with zero heap allocations, while the strict RFC 8259 JSON bridge rejects UTF-16 surrogate traps and round-trips whole floats (1.0) and {"$bytes":"..."} losslessly.

Direct Architectural Win · Plane A 169.8 ns/frame zero-allocation canonical verification (278.7 ns including hardware SHA-NI 34-byte CID, 7.43× faster than full decode), 100% cross-language CID identity across 150 frozen test vectors, live vLLM V1 prefix-cache hits when JSON keys arrive reversed, and permanent document CIDs across model upgrades.

Plane B · Progressive Attention LensesZero-Inference Mipmaps, 47-Bit Alpha Handles & Fence Breakout Protection

Graphics engines never sample a 4K texture for a twelve-pixel surface; they store mipmaps and read only the resolution the camera needs. Cowrie's Plane B applies the same principle to LLM context windows with zero summarizer inference: R0 emits a 10-letter lowercase Alpha32 handle (@kmpqvwrxzt, 47.0 bits of collision entropy across ~12M records while avoiding Qwen3.5's \p{N} single-digit BPE fragmentation), R1 emits a typed structural outline, R2 hoists uniform table headers (len >= 3, density >= 0.70) while keeping raw tensors behind <T:i8[512]@space> pointers, and R3 returns the lossless record on demand. To stop untrusted strings from forging boundary markers inside prompts, R2 escapes interior <<< and >>> sequences automatically.

Direct Architectural Win · Plane B −98.7% W2 multimodal tokens (17,899 → 241), −73.8% R0 handle token cost, −99.8% R0 / −97.5% R1 Creative Studio Vault wire bytes (12,525 B → 28 B / 313 B), zero fence-breakout escapes, and 1.93×–4.43× faster live paired QA at 24/24 (100%) accuracy parity.

Plane C · 16 KB Hardware ArenaUniversal Page Alignment, O_DIRECT Pinned DMA, vLLM Offloading & Live CWIV Compaction

Hardware page sizes diverge across silicon: x86 Linux defaults to 4,096 bytes, Apple Silicon unified memory uses 16,384 bytes, Android ARM64 mandates 16,384 bytes, and CPU SIMD cache lines are 64 bytes. Aligning Plane C to their exact least common multiple, 16,384 bytes (align_log2 = 14) with strict 0x00 padding, lets one file map zero-copy across Linux GPUs, Apple Silicon Macs, and mobile devices while satisfying kernel O_DIRECT alignment on NVMe.

Three Plane C modules turn that page floor into order-of-magnitude latency gains. First, CWSP StatePages checkpoint live GPU state via O_CREAT | O_EXCL 0600 temp files + parent-dir fsync using split precision (exact F32 DeltaNet SSM + Q4_0 GQA KV in llama.cpp, and native multi-layer paged KV blocks in vLLM 0.15.0 via CowrieKVConnectorV1), bound to a 64-stride cowrie_model_fingerprint (1.86 ms on 5.59 GiB), runtime_id, optional RFC 2104 HMAC-SHA256, and 4 MiB parallel SHA-NI / ARMv8 SHA2 verification. Double-buffered 16 KB O_DIRECT into cudaHostAlloc pinned memory across two CUDA streams lifts cold NVMe-to-VRAM bandwidth 1.31× (3.38 GB/s cold; 26.79 GB/s warm PCIe Gen4). Second, CWIV IVF blocks co-locate embeddings and 16-byte authority metadata for concurrent O_DIRECT search. Third, LiveIvfStore (.cwwal) appends new frames or INT8 vectors to a SHA-256 hash-chained WAL in 4.45 µs and compacts 50,500 vectors into a sealed 16 KB CWIV shard in 12.91 ms.

Direct Architectural Win · Plane C 49.7× cold NVMe / 123.2× warm Q4_0 resume in llama.cpp, 5.64× cross-restart KV restore (80.5 ms vs. 453.9 ms) in vLLM 0.15.0, 3.38 GB/s cold O_DIRECT / 26.79 GB/s warm CUDA DMA, 7.07 ms 10M-vector NVMe search, and 87.5 µs live WAL-delta hybrid search.

04Engineering Postmortem, Security Audit & Formal Verification

Eleven Troubles We Hit, Audit Catches, and Non-Bolt-On Bend Proofs

Every sharp invariant in Cowrie v1.2 exists because a simpler design broke under adversarial fuzzing, physical NVMe benchmarking, live hybrid-model testing, security auditing, or formal proof obligations in Bend 2.0.35. Recording all eleven catches explains why the specification looks the way it does and defines the exact boundaries where formal methods and Cowrie itself stop.

01

Adversarial OOM & stack-overflow bombs broke our first Rust decoder

Crash → ≤ 23 µs, 0 allocs
Trouble Hit
Our first decoder passed 150 clean round-trips, then panicked on a forged array claiming 1B elements (Vec::with_capacity OOM) and blew the call stack on 500 nested arrays.
Design Choice Forced
Froze hard MAX_DEPTH = 64 and strict byte-bounded pre-allocation (count <= remaining_bytes) into the wire spec, rejecting 8/8 DoS bombs and 99/99 truncations in ≤ 23 µs.
02

Software SHA-256 erased the StatePage restore speedup

2,800 ms → < 0.6 ms warm
Trouble Hit
Restoring a 505 MB FP16 StatePage from RAM took 60 ms, yet hashing it with single-threaded scalar SHA-256 (~180 MB/s) took 2.8 seconds, erasing the GPU prefill savings.
Design Choice Forced
Adopted 4 MiB Merkle leaves hashed in parallel via runtime-detected x86_64 SHA-NI and ARMv8 SHA2 instructions (1.92 GiB/s per core), keeping verification under 0.6 ms warm.
03

Linux /tmp (tmpfs) masked real cold NVMe latency

RAM illusion → /dev/nvme1n1p3
Trouble Hit
Early cold-restore runs placed StatePages in /tmp, which on Linux is RAM-backed tmpfs rather than NVMe flash, hiding real PCIe storage latency.
Design Choice Forced
Relocated every cold StatePage and 10M-vector benchmark onto physical NVMe (/dev/nvme1n1p3) with explicit POSIX_FADV_DONTNEED page-cache eviction between runs.
04

Split embedding/metadata file layout missed the 10M-vector target at 64.81 ms

64.81 ms miss → 7.07 ms PASS
Trouble Hit
Placing 5.12 GB of embeddings in one file region and 160 MB of metadata in a second forced 32 serial QD=1 pread() seeks, leaving 15 of 16 NVMe queues idle.
Design Choice Forced
Co-located [embs_c || meta_c || 0x00 → 16 KB] inside contiguous CWIV blocks with 16 concurrent O_DIRECT reads and AVX2/NEON INT8 SIMD kernels (7.07 ms).
05

Uniform quantization drifts recurrent SSM state in hybrid architectures

Temporal drift → Split Q4_0 + F32
Trouble Hit
In hybrid Qwen3.5 models (24 DeltaNet SSM + 8 GQA layers), quantizing recurrent SSM matrices compounds error multiplicatively step over step across long contexts.
Design Choice Forced
Enforced split-precision StatePages (Q4_0 KV + exact F32 SSM) with distinct wire error gates (ERR_KV_QUANT_MISMATCH, ERR_SSM_DTYPE_MISMATCH).
06

Tokenizer digit splitting & polymorphic AST hoisting regression

+2.2% AST bloat → Alpha32 + adaptive R2
Trouble Hit
Qwen3.5's \p{N} pre-tokenizer split every digit of hex hashes into separate tokens, while table hoisting added +2.2% tokens (137 → 140) on polymorphic AST trees.
Design Choice Forced
Adopted digit-free lowercase Alpha32 pointers and gated R2 header hoisting on len >= 3 and key density >= 0.70, falling back to compact JSON automatically.
07

2-hop taint laundering & model-upgrade CID churn

12/12 bypass → sticky 0x80 & satellites
Trouble Hit
Checking only immediate frame authority (0x04) missed 12/12 multi-hop LLM summarization attacks, while hashing KV caches inside document CIDs broke links on weight upgrades.
Design Choice Forced
Enforced sticky causal BIT_TAINTED = 0x80 across all parent CIDs and kept all model-dependent CWSP/CWIV caches strictly outside Plane A CoreHash.
08

Audit catch: unhashed Plane C shard tensors & /tmp StatePage poisoning

v1.0 gap → 0x04 dual Merkle + HMAC
Trouble Hit
Our v1.0 CWRF Merkle root hashed Plane A frames while leaving raw Plane C tensors unauthenticated, and head-only model hashes plus predictable .cowrie.tmp paths risked mid-layer LoRA misses or /tmp symlink swaps.
Design Choice Forced
Bound 48-byte 4 MiB tensor Merkle digests into a dual-tree 0x04 root, hardened saves with O_CREAT|O_EXCL 0600 + fstat UID/mode checks + runtime_id + optional HMAC-SHA256, and unified 64-stride model fingerprinting (1.86 ms).
09

Audit catch: fail-open unknown IDs, 28-bit handle collisions & R2 fence spoofing

Fail-open → 6/6 fail-closed HTTP 403
Trouble Hit
In ec_cowrie.c, unknown or empty argument IDs and parents past index 32 were skipped rather than tainted; 6-letter handles had a ~17K birthday bound; and raw strings could embed fake <<<END:COWRIE>>> fences.
Design Choice Forced
Made unknown, empty, 8-hex prefix, and colliding IDs fail closed (HTTP 403), removed the 32-parent cap, expanded trust storage to 4,096 untainted-first slots, widened handles to 10 letters (47 bits, ~12M birthday bound), and escaped inner <<< markers.
10

Audit catch: allocating verifier, UTF-16 surrogate underflow & thread spawn storms

1,261 ns → 169.8 ns + WorkerPool
Trouble Hit
cowrie_frame_verify allocated full Value trees and a HashSet just to check wire validity; \uD800\u0041 underflowed cp2 - 0xDC00 in JSON parsing; and thread::scope spawned OS threads per call.
Design Choice Forced
Built zero-allocation verify_frame_zero_alloc (169.8 ns, 7.43× faster than full decode), added native TAG_TENSOR_REF = 0x0A (−47.4% bytes), fixed RFC 8259 surrogate/float/bytes round-trips, wrapped FFI in catch_unwind, and added a persistent 16-thread WorkerPool.
11

Formal verification & spec-tightening catch (Bend 2.0.35 --verdict): underspecified laws plus 8 real wire & fence bugs (F1–F8)

8 bugs caught → 26/26 laws + 13/13 mutants
Trouble Hit
Our first 15-law pass caught <<<<END:COWRIE>>>> fence reformation (F1), unauthenticated CWZM bounds (F2), and CWRF slack bytes (F3), yet an adversarial recheck showed one-sided safety laws still passed trivial deny-all gates, taint-all ledgers, and wipe-string sanitizers while omitting structured paths: raw hoisted R2 table column headers (F4), global-HashSet zombie .cwwal tombstones blocking re-insertion (F5), partial $tensor/$bytes map fallback (F6), empty StatePage runtime_id bypasses (F7), and TensorRef space = "embed>>" + closing > forming >>> (F8).
Design Choice Forced
Tightened formal/PROOF.bend to 26 biconditional and liveness-preserving laws checked by Bend 2.0.35's Lean-proven BendTT kernel in 218.3 ms (0 @unsafe, 13/13 fail-open and anti-underspecification mutants rejected), closed all eight Rust bugs, and locked compiled CowrieKernel.bend (.mjs) across 2,000 differential vectors against cowrie_core.wasm and libcowrie_core.so (keeping 255-bit Curve25519 arithmetic and SIMD intrinsics on RFC/differential tests).

05Systems Implications

What This Means for Local LLMs vs. Cloud Fleets

Local workstations and multi-tenant cloud clusters suffer from opposite scarcities (VRAM capacity and daemon overhead on a desktop versus prefill FLOP cost, spot preemption, and cross-tenant provenance in a datacenter), yet the same container primitives reshape the economics of both.

For local LLMs, creative studios, and edge devices

A single 24 GB RTX 3090 or unified-memory MacBook cannot keep ten coding sessions, FLUX.2, Wan 2.2, TRELLIS.2, and ACE-Step resident in GPU memory simultaneously. Cowrie turns local NVMe into a 21–96 ms warm virtual-memory swap tier for neural state and ComfyUI DAGs: users switch repositories, close their laptop, or bounce between chat and video generation without paying multi-second prefill penalties. Meanwhile, 16 KB CWIV search puts 10 million filtered vectors on one local SSD with zero external daemon, ARMv8 SHA2 + 16 KB alignment run natively on Apple Silicon and Android, and fail-closed 0x80/0x84 taint makes local shell tools and community workflows mechanically safe.

For cloud serving clusters and enterprise agent fleets

In production cloud serving, prefill tokens and idle HBM residency dominate GPU bills. Cutting structured RAG and tool payloads by 65%–98.7% via R2 directly lowers quadratic prefill FLOPs and TTFT, while 169.8 ns zero-alloc verification and canonical key sorting eliminate ingress CPU spikes and silent prefix-cache misses across polyglot SDKs. Even larger is authenticated stateless pod elasticity: because a 13.8K-token session compresses to 180.2 MB inside an HMAC-SHA256 authenticated CWSP satellite bound to (model_sha, runtime_id, kv_quant, ssm_dtype), clusters can offload idle tenant KV/SSM state from HBM GPUs to NVMe or object storage and thaw it safely on any replacement pod during autoscaling or spot preemption.

06Roadmap

Future Work

With 16 KB CWZM zone-maps, crash-safe .cwwal + LiveIvfStore compaction, symmetric 4-runtime KV/StatePage + WAL + Ed25519 parity (vLLM, llama.cpp, Eureka LLM, Eureka Creative v7), cowrie mcp-proxy, O_DIRECT dual-stream CUDA DMA, and zero-import wasm32 (80.4 KiB gzipped) shipped and verified in v1.2.0, four frontier milestones remain across datacenter silicon, browser GPUs, and upstream model ecosystems:

01

Datacenter GPUDirect Storage (nvidia-fs BAR1 P2P) & Apple Metal MTLBuffer

Datacenter & Apple Silicon

Consumer GeForce GPUs (including our RTX 3090) disable PCIe BAR1 P2P DMA in driver firmware, making v1.2's double-buffered 16 KB O_DIRECT + dual-stream cudaHostAlloc pipeline (3.38 GB/s cold) the hardware ceiling on desktop Linux. On A100/H100/B200 nodes with nvidia-fs.ko loaded and on Apple Silicon unified memory (makeBuffer(bytesNoCopy:)), the exact same 16 KB Plane C offsets map straight into GPU virtual memory with zero host copy.

02

Upstream Qwen3.5 hybrid SSM+KV parity in vLLM & SGLang HiCache

Waiting on upstream model support

Extend CowrieKVConnectorV1 from pure-attention Qwen3ForCausalLM to split-precision recurrent DeltaNet SSM + GQA KV blocks inside vLLM V1 and SGLang HiCache once upstream releases native Qwen3_5ForConditionalGeneration support.

03

Attention-sink mixed KV precision for 128K–1M token horizons

FP16 sinks + Q4_0 / FP8 body

Extend CWSP layout_ver = 2 descriptors to keep initial attention-sink tokens and the recent rolling window in exact FP16/BF16 while quantizing the interior context body to Q4_0 or FP8 for ultra-long horizon stability.

04

WebGPU zero-copy views over shipped wasm32 & hardware FIDO2 security-key signing

WebGPU GPUBuffer & YubiKey UX

With cowrie_core.wasm (188.9 KiB raw / 80.4 KiB gzipped, 0.59 ms load) now shipped and verified in Chrome 135, the remaining client-side step is mapping 16 KB Plane C byte slices directly into WebGPU GPUBuffer views and binding COWRIE_DECLASSIFY_V1 Ed25519 signatures to hardware YubiKey / TouchID touch confirmation.

07Summary

Summary

  • Why Cowrie exists: Five decades of format specialization split human text (JSON), fast RPC (Protobuf), content hashing (DAG-CBOR), columnar scans (Parquet), and static weights (Safetensors/GGUF), leaving AI requests to cross six incompatible layers with broken caches and no hardware-enforced privilege wall.
  • Complete v1.2 architecture: One zero-dependency Rust core (799 KB libcowrie_core.so + 80.4 KiB gzipped cowrie_core.wasm) unites 169.8 ns zero-alloc canonical verification + native TAG_TENSOR_REF (0x0A) (−47.4% bytes) in Plane A, 47-bit 10-letter handles + fence-escaped R0–R3 lenses in Plane B, 16 KB 0600 HMAC CWSP StatePages + 4-runtime longest-prefix KV offloading + O_DIRECT dual-stream CUDA DMA + LiveIvfStore (.cwwal + CWIV) in Plane C, and dual-tree 0x04 Merkle roots + 16 KB CWZM zone-maps + RFC 8032 Ed25519 declassification + cowrie mcp-proxy in Plane D.
  • Fifteen receipted wins across four symmetric engines, MCP & WebAssembly: 49.7× cold / 123.2× warm Q4_0 resume and 13.72× suffix reuse (9.01 ms) in llama.cpp, 5.64× cross-restart KV restore (80.5 ms) & −69.7% R2 tokens in vLLM 0.15.0, 3.38 GB/s cold O_DIRECT / 26.79 GB/s warm CUDA DMA, 1.58×–2.88× faster cold NVMe point/range filters than SQLite3 (0.51 ms vs. 1.03 ms), 4.45 µs .cwwal appends + 87.5 µs hybrid vector search, 13.15 µs wire-level MCP taint blocking with Ed25519 owner approvals across all four runtimes, 0.59 ms load / 1.74 µs verify in Chrome wasm32, 151.7×–2,970× Creative v7 restarts, 1.0–9.6 ms ComfyUI DAG hits, 7.07 ms 10M-vector NVMe search, and 41,661× Merkle delta sync.
